# Workflow: Style Selection and Comparison

Choose a visual language for a problem, or compare candidate styles honestly.

**Inputs:** the design problem, audience, brand context, medium, constraints.
**Outputs:** one primary style, zero to two supporting influences, named conflicts, rationale.
**Load:** [../references/style-catalogue.md](../references/style-catalogue.md) and the relevant `../references/styles/*.md` category files; [../references/cross-disciplinary-design.md](../references/cross-disciplinary-design.md) when influences cross media.

## Steps

1. **State the problem before any style word.** Purpose, audience, emotional register required (trust, energy, calm, authority), information density, lifespan of the artefact, implementation medium.

2. **Derive selection criteria.** From step 1, write 3-6 testable criteria, e.g. "must read as credible to risk-averse banking buyers", "must survive at 1080x1080 thumbnail size", "team can only implement with CSS, no 3D".

3. **Shortlist candidates.** From the catalogue, pick 2-5 styles whose central philosophy serves the criteria. Read their full entries, including "when not to use" and "common mistakes". Reject candidates on their own documented limitations, not on taste.

4. **Check conflicts.** For each surviving candidate, list the styles and influences that conflict with it (the catalogue entries name them). If the user requested conflicting styles together, say so explicitly, define which influence dominates at which level (structure, surface, accent), and resolve the hierarchy rather than blending everything equally.

5. **Select.** One primary direction. Supporting influences only where they do a specific job the primary cannot. Write the selection sentence: "Primary X because [criteria met]; Y supports [job]; rejected Z because [documented limitation or conflict]."

6. **Translate to system implications.** What the choice means for grid, type, colour, depth, motion and density in this medium. A style name alone is not a deliverable.

7. **Sanity-check against imitation.** Confirm the plan uses the style's principles rather than cloning a famous artefact of it. The catalogue's "apply without imitation" note is the test.

## Comparison variant

When the task is "compare styles" rather than "pick one": present each candidate against the same criteria table, state where each wins, and still end with a recommendation and its trade-offs. Refusing to recommend is a failure of the DECIDE mode.

## Gate

Done only when: criteria preceded candidates; at least one plausible style was rejected with a reason; conflicts are named; the selection sentence is written; system implications are concrete. If every candidate "could work", the criteria were too weak: tighten them and re-run.
