# Candidate C: the catalogue field

Direction: the 64-style catalogue made visible as a specimen sheet; 64 abstract marks on one construction grammar, parted by a calm central clearing that carries the name.
System: 80px cells on a 16-column grid (two 2-row strips, full bleed); each mark lives in a 48px box on a 6px construction grid, one stroke weight (3), butt caps, families scattered by a coprime stride (k*21 mod 64) so the texture stays even; paper #F5F2EA / #ECE8DD, mark ink #4A4F57, text ink #16181C, one vermilion accent bar sized to exactly one cell of the name's mono grid.
Type: name in bold system mono (ui-monospace/Menlo/Consolas stack) at 124px, spelled `design-styles`; proposition in system sans at 31px; both inside the 64px safe margin, marks alone may bleed.
Copy honesty: proposition is README line 1 plus the verification loop; "64 styles / principles, not presets" is the README's own claim; no numbers from the evaluation, no badges, no logos.
Excluded: dark/neon and gradient registers (AI-slop adjacency), mock UI chrome, any mascot-style logo, colour-coded meaning, per-mark colour variety (confetti risk); the field stays two inks so the clearing wins.
Risk: the paper ground is unfashionable beside dark-mode feeds; it must sell as deliberate print-register restraint, and the mark field must never be mistaken for decorative dingbats.
Verified: XML parse (ElementTree); headless Chrome renders at 1280x640, 400x200, and 2x (2560x1280); inspected all three; checked composition against dark (#0d1117) and white page surrounds with 8px corner rounding; fixed what renders exposed (hierarchy: name widened past the proposition; squat off-centre spiral mark rebuilt on the grid). Text contrast: 15.2:1 name, 12.6:1 prop, 5.9:1 annotation on their own grounds.
Unverified: raster on non-Chromium rasterisers (mono fallback metrics may shift name width slightly; left-aligned layout tolerates it).
